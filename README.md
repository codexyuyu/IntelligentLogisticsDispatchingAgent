## 前期调研记录

下文及 [demo.zip](demo.zip)、[demo 工程骨架](demo/README.md) 保留为前期调研和教学资料，其日期、目录及旧排期不作为当前执行状态或任务来源。

面向大学生创新训练与智慧物流命题的工程设计骨架。目标是把自然语言需求转换成可核验的仓储、运输和异常调整方案，并用仿真与对照实验说明效果。

**历史状态（2026-09-09）：已完成文档骨架和三个可运行计算 demo，当时 11 项测试通过；完整仓运联合系统与前端尚未实现。** 原始申请书保留在工作区根目录。小 demo 的单次耗时不能视为完整系统性能。

建议采用 FastAPI + React + PostgreSQL 组织应用，以 OR-Tools Routing 处理运输、CP-SAT 处理仓储排程、独立校验器检查完整方案，SimPy 提供事件回放与推演。万悟平台作为可选适配入口。核心结构参考 [FastAPI 官方全栈模板](https://github.com/fastapi/full-stack-fastapi-template)，仓储业务概念参考 [InvenTree](https://github.com/inventree/InvenTree)。

## 工程目录

```text
backend/app/
  domain/          业务对象与独立校验规则
  application/     调度用例、影响分析、四角色协商
  ports/           求解器、仿真、存储、模型的少量替换接口
  adapters/        OR-Tools、SimPy、PostgreSQL、模型与路网实现
  api/             FastAPI 请求转换与访问控制
backend/tests/     未来的约束、事务与接口验收
frontend/src/
  features/        订单、仓储、车辆、计划、异常、实验页面
  client/          根据 OpenAPI 生成的接口客户端
  components/      共用展示组件
contracts/         跨模块交换约定，暂为文档
data/scenarios/    合成场景和外部数据来源约定
data/external/     已下载的公开实测数据、许可台账与 manifest
benchmarks/        对照实验与结果规范
platform/wanwu/   平台接入与工作流留档
deploy/           最小部署与离线演示设计
docs/             调研与工程决策
demos/            独立计算探针、反例测试和运行记录
```

每个目录内有职责说明。三个 demo 在独立虚拟环境中已运行并记录依赖版本；正式后端仍处设计阶段。下一里程碑是“2 仓、4 车、20 单”的结构化输入调度闭环，同时验证团队选用的模型工具调用。用户已确认万悟非必需；开发 9 周，第 10 周集中测试与修复，详见实施路线。

## 工程约束

- 业务核心不依赖 Web 框架、数据库对象或模型 SDK；替换其中一项不应改写领域规则。
- 只有经过独立校验、基于当前数据版本的计划才可确认。未知、超时、过期都不能包装成成功。
- 大模型负责理解与解释，不直接编造订单、道路数据、资源容量和最终排程。
- 第一版用一个代码仓库、一个后端应用和一个数据库；求解在受限工作进程运行。
- 每个实验注明场景、随机种子、版本、硬件和时间口径；合成数据与实测数据明确区分。

项目自身许可证尚未指定。本轮未复制第三方业务源码；后续复用按选型文档保留出处、版本与许可证。
