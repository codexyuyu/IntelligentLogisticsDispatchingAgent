## 已确认缺口

Operation 与 ScheduledOperation 仅有单个 resource_id。当前没有存储占用区间、初始存量轨迹、序列准备策略、累计暴露区段。changes 目录原先只有 TEMPLATE.md。不能把丢失字段的准备快照当作完整 R05 输入。

## 请求乙方冻结的语义与字段（建议，非已发布接口）

1. 存储资源：storage_location_id、warehouse_id、temperature_zone、capacity_units、容量单位与规则版本。容量单位必须与占用数量一致，不混用件/托盘/体积。
2. 存储占用：occupancy_id、batch_id、location_id、quantity_units、入库完成/出库开始的工序引用及计划区间。初始库存单独声明数量、位置与离库时刻；期末仍存库的覆盖至 horizon_s，不能遗漏。区间采用 [start_s,end_s)，同一时刻先释放后占用；峰值容量按每段核查，不能只比较积分。
3. 多资源：每工序具名资源需求集合（resource_id、quantity_units），同一工序的所有需求占用同一执行区间；结果必须列出实际资源分配。缺少任何必需需求即失败。
4. 换批：setup_policy_id/version、资源初始 setup_class、每个前类→后类的 duration_s；只约束资源上相邻任务，首项与初始状态比较。准备需人员/设备时输出显式准备工序和资源占用，不能仅留空档。缺切换规则不能默认为 0。
5. 预冷：货物/资源要求、最短时长、目标温区、对应预冷工序及与装载的先后关系。独立验证检查实际区间与资源资格，不能只检查 operation_kind 文本。
6. 暴露：订单/批次 max_exposure_s、暴露区段 start_s/end_s、来源和覆盖范围（仓内、等待、装卸、运输）。按同一货物区间并集累计，重叠观测不重复计时；未知区段不得视为零。保鲜 expires_at 与 origin_at 的换算规则保持时区明确。
7. 相容性：位置/资源温区和批次相容策略及版本；检查整个重叠区间，不能只检查入库瞬间。
8. 校验输入必须提供请求、完整候选结果、规则版本及来源；输出复用 ValidationReport，违规附 rule_id/object_ids/区间和容量证据。必需数据缺失不返回 passed。领域层纯标准库，映射在 application/adapter，不导入 Pydantic 或求解器。

请乙方同时冻结 DTO 名称、字段必填/可空语义、领域映射调用签名、结果格式及兼容迁移。上述名称是提案，不授权甲方复制 DTO 或直接更改公共契约。

## 手算正反例（冻结后转为测试，不声称已执行）

| 规则 | 正例 | 反例与预期 |
| --- | --- | --- |
| 峰值库容 | 容量10，6件[0,10)、4件[5,15)，峰值10 | 第二批5件：在[5,10)峰值11，失败 |
| 同时释放入库 | 容量6，6件[0,10)、6件[10,20)，峰值6 | 第二批9秒开始，峰值12，失败 |
| 初始库存 | 初存4件到20秒，后入6件[5,10)，峰值10 | 后入7件峰值11；遗漏初存不能通过 |
| 多资源 | 任务[0,10)同时占月台1与工人1，两者容量1 | 同时另一任务占该工人，失败；漏工人分配也失败 |
| 换批 | A结束10，A→B需3秒，B开始13 | B开始12，失败；不对非相邻任务重复扣准备 |
| 初始换批 | 初态A，首项B需3秒，B开始3 | B开始2，失败 |
| 预冷 | 最少30秒，预冷[0,30)、装载开始30 | 预冷仅29秒或装载开始29，失败 |
| 累计暴露 | 上限120，区段[0,60)、[100,160)，累计120 | 后区段至161，累计121，失败 |
| 暴露重叠 | [0,80)、[60,100)，并集100 | 无覆盖数据：not_checked/unsupported，不能 passed |
| 温区与相容 | 冷藏批次进入冷藏位置且重叠批次相容 | 冷冻批次入冷藏位置，或禁混批重叠，失败 |
