# B-04 前端局部重调度修复（2026-09-21）

本次仅在现有框架内修复异常处置链路，不改变 FastAPI/OR-Tools/SimPy/接口契约的整体架构。

修复内容：
1. 异常事件接口返回 `result=null` 时，前端会查询 `replanning_job_id`，将后端失败原因展示出来，避免页面卡在“已受理”。
2. 异常处置按钮不再因为 `accepted` 状态被永久禁用；失败可重试，成功后显示完成状态。
3. 保留 `departure_delayed` 作为当前 B-04 唯一真实支持事件类型，未接入的异常继续明确禁用。
4. 将事件触发的 B-04 默认求解预算从 10s 调整为 60s，并按多仓库剩余仓库数分配预算，避免前一个仓库耗尽全部预算导致后续仓库无预算。
5. 未修改 API 路由、数据契约、前端整体架构或其他 B 模块算法接口。

验证：
- `npx tsc --noEmit`：通过
- `pytest -q`：36 passed
- 当前 Linux 环境 `vite` 可执行权限异常，`npm run build` 未能在此环境完成；Windows 上重新 `npm ci` 后再运行即可。
