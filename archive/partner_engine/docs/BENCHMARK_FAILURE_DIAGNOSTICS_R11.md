# B-06 批量实验失败诊断 R11

本次只修改前端实验页，不修改后端整体架构、Planning Job、CP-SAT、Routing、SimPy、OpenAPI 或数据库。

## 新增能力

- 每个 S20/S50/S100 + seed 结果保留成功/失败状态。
- 失败记录保存失败阶段：场景导入、Planning Job 提交、CP-SAT + Routing 求解、方案读取、指标计算或未知。
- 失败记录保存 error code，并根据已知错误类型给出可读诊断原因。
- 批量实验结果写入当前浏览器 localStorage，刷新页面后可恢复。
- CSV 增加失败阶段、错误码、失败原因和任务 ID。
- 汇总只统计成功运行项，失败项单独展示，不以 0 填充成“成功结果”。

## 运行链路

1. 生成固定规模 + seed 的场景。
2. 导入场景。
3. 提交现有 Planning Job。
4. 等待任务结束并读取 plan。
5. 计算规则基线与优化指标。
6. 成功则记录 metrics；失败则记录 stage/error code/reason，并继续下一个 seed。

## 说明

S50/S100 失败时，页面现在可以先判断失败发生在哪一层，再决定是否需要调整场景生成或求解预算；不会为了让实验表看起来完整而伪造成功结果。
