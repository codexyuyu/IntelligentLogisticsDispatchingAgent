# R15：B-06 实验可信度与证据归档版

## 版本定位
- 基于 `915_B06_TWIN_REFRESH_BENCHMARK_R14` 增量修改；不改现有 React + FastAPI + OR-Tools + SimPy 项目架构。
- R14 的 S20/S50/S100 × 5 用户实跑数据属于**历史基准（R14-v1 场景与统计口径）**。R15 修改了合成场景生成和指标口径；**禁止把 R14 的百分比直接沿用成 R15 的实验结论**。
- R15 旨在检验“方案是否正确”和“对照是否公平”，不保证仍能产生原来的 17.6% / 49.3% / 58.7%。

## 实际修改
1. `frontend/src/lib/benchmark.ts`：规则基线不能把缺失矩阵距离当作 0；重新模拟车辆出发、仓库交接、容量、服务窗口、新鲜度时限、返回班次，车次超时不接单。新版本为**共享仓储交接方案后的贪心运输规则基线**，不是另一套完整的 CP-SAT+Routing 联合方案。
2. 同文件：逐订单、逐路线检查方案，包括：后端验证状态、订单唯一覆盖、车辆与温区、运输起终点、容量、服务时间窗、仓库交接时间、路段连续性、里程核对等。违规时将批量实验标记为**指标校验失败**，不会显示成功的距离优化率。
3. `frontend/src/lib/batchBenchmark.ts`：对不同 Seed 的同仓同温区配送节点作确定性重分配（从已有矩阵中的合法节点选取），并保留既有数量和时间窗扰动。新生成器标为 `r15-synthetic-v2`，不是生产订单数据。记录实际浏览器端到端耗时与 warehouse/routing 阶段报告耗时；区分配置预算 60000 ms。
4. `frontend/src/features/experiments/Page.tsx`：页面在基线与优化方案均完整服务订单时才展示距离改善率，否则明确“不可比”。添加需求覆盖/验证、端到端耗时、合并保留不同规模的历史、完整 JSON 证据包导出，CSV 增补各阶段时间、校验、输入指纹等字段。
5. 数据留存上限为 40 组最近实验，每组 JSON 证据包含输入 Snapshot 与诊断字段。旧 R14 的 `localStorage` 键和新 R15 键分离，互不覆盖。**浏览器缓存并非永久数据库，运行完务必导出 JSON 与 CSV。**
6. `frontend/scripts/test-r15-evidence.cjs`：为统计与证据逻辑增加无后端核心单元测试。

## R15 本地验收顺序
1. B-06 → S20 × 5（Seed 17,42,66,88,101）。查看逐条结果中的方案校验状态、订单满足率及“对比口径”是否可比。
2. B-06 → 仅 S50 × 5；注意结果会累积，而不是覆盖 S20。再仅 S100 × 5。导出 JSON 证据包 + CSV。
3. 检查 S20/S50/S100 的**实际订单覆盖、未服务订单、方案验证**。对于“不可比”的实验，先查看规则基线与优化方案的未服务订单数量，再决定是否改进基线，**不要为迎合旧百分比降低硬约束**。
4. 检查各 Seed 场景指纹、配送节点差异、仓储/运输阶段耗时、端到端耗时与预算。端到端耗时包含轮询和网络，不应伪装成求解器纯计算时间。
5. 将本次 CSV 和 JSON 发回进行分析，决定下一阶段 B-04 异常重排对照实验。
