# R25 · 流畅回放 / 四车联动 / OSRM 3D 道路展示

## R25 改动范围

- `useSimClock`：单一高精度时间源 (`getTime()`)，Three.js 逐帧读取；React 状态最多约 12.5 次/秒刷新；暂停、seek 与触底结束仍立即更新。浏览器后台帧时间按 100 ms 截断以免突然跨越一段回放。
- `DigitalTwin3D`：从每帧全树 React 重渲染及频繁 WebGL 重新初始化，改为**按路线/场景数据签名创建场景**；更改时间、选车、跟车、受影响状态不重建 renderer。`ResizeObserver` 调整尺寸，卸载时释放 three geometry/material/texture。设置 DPR 上限 1.5。
- `lib/replayPaths.ts`：为每个实际停靠段建立路径长度表，按 `departureS/arrivalS` 运行、服务时间不移动；示意模式是明确标注的城市折线路径而不是以前贯穿停靠点的 Catmull-Rom 曲线。选择车辆时可跟随镜头；车辆包含冷机、厢体、驾驶室、轮胎、灯与温区标识。
- `lib/fleetDemo.ts`：从当前应用已加载的**四辆车和订单编号**，形成四条不同的、错开发车时间的**可视化演示路线**，不输出/保存调度计划，不写数据库，不暗示通过 OR-Tools 约束校验。少于四辆车时按钮禁用，不凭空增加车辆。
- `仿真回放` 页面：可切换 **真实规划** / **四车演示**；异常和 SimPy KPI 只表示原真实仿真结果，不会被四车动画伪造。提供每车跟车镜头与完整播放控制。
- `数字孪生驾驶舱` 页面：也可切换四车演示、实际规划和车辆镜头。业务 KPI 仍来自实际规划，不因演示动画修改。
- `PostgreSQL 实库调度` → `运行路线预览`：跑出路线后可打开 **R25 3D 道路动态回放**，拥有独立进度条、倍速和车辆跟随；可选 OSRM 时直接投影 OSRM GeoJSON 路网并按对应车辆停靠顺序推进。后端 OSRM 预览添加 `stop_coordinates`，是已有真实节点坐标的*附加只读数据*，不变更共享业务合同与持久化结构。

## 正确区分两种路线来源

1. **真实规划路线 / 路形示意**：R20 求解产生车辆/站点/时刻，当前若缺少 OSRM 几何，则城市折线仅用于展示，不是真实道路；实际是否只用两车由求解器决定。
2. **四车演示**：来自当前导入场景的四辆车和全部订单，四条独立示意行驶线是为了展示交互流畅度和效果；**不继承真实路线的可行性、保鲜温控或接单结论**，也不和 SimPy 事件一一对应。
3. **OSRM 道路模式**：需要运行的 OSRM driving 服务与覆盖实际订单/仓库所在城市的路网数据。FastAPI 给出真实 OSRM GeoJSON 线路以及站点坐标，3D 投影后沿折线按各段到离时刻移动；这属于道路网络*估计*，不是 GPS 实时位置、实时堵车，也不等于可执行冷链配送方案。`stop_coordinates` 用真实 PG node 坐标而不是模型推断；找不到时禁用该功能而不伪装路线。

## Windows 运行（不需要重建已创建的 R24 数据表）

1. 解压 R25 ZIP 到**新文件夹**，关闭旧后端（8000 端口同一时间只能运行一个），保留 R24 ZIP / 数据库备份。
2. `backend` PowerShell：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\start_pg_r25_local.ps1
   ```

   R25 新版脚本含 UTF-8 BOM，兼容 Windows PowerShell 5.1 的中文编码；输入 PostgreSQL 密码。已建过 R24 表就**不要再加 `-CreateR24Tables`**。
3. `frontend` PowerShell：

   ```powershell
   npm ci
   npm run build
   npm run dev
   ```

   打开 `http://127.0.0.1:5173`，进入左侧「仿真回放」或「数字孪生驾驶舱」，在 R25 工具条中选择「四车演示」，点击播放/跟车/拖动时间轴。必要时先点击「开始完整案例」或「只生成基线」，确保应用已加载 20 单双仓四车场景。
4. 如已部署与 PG 实际地址对应的 OSRM 服务，后端可用下列命令启动：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\start_pg_r25_local.ps1 -OsrmBaseUrl 'http://127.0.0.1:5000'
   ```

   切到「PostgreSQL 实库调度」→「运行路线预览」→「行驶矩阵来源：OSRM 道路估计」，运行后按「打开 3D 回放」。若 OSRM 不可达，会明确报错，不允许自动降级并冒充真实路网。若用旧直线模式，则新 3D 页面明确标为「示意道路」。

## 最小验收建议

- 正常打开 3D、播放/暂停、进度条拖拽到中间和末尾；确认不需要重新创建 WebGL 画布。
- 仿真回放点击四车演示，看到四辆不同车、独立路线和发车时刻；点各个「跟车」观察摄像机位置，再返回全局视角。
- 切回「真实规划」，车辆数量回到实际求解器结果（可能是两车）。
- 确认 PostgreSQL 20 单、4 辆车、旧归档/地图、`readiness` 依旧可见；不要归档示意路线为正式业务计划。
- OSRM 实际可用时再做路网 3D 验收；没有服务不妨碍四车演示和原功能。

## 已知边界 / R26 待办

- **尚未在用户 Windows 浏览器上进行 FPS 定量测试**；本版从架构上移除频繁重建/WebGL 状态同步问题，并限制渲染 DPR，实际流畅度仍依赖显卡性能、浏览器、道路坐标数。
- 四车展示模式为明确的演示动画，不保证真实容量、班次、交通可行。正式使用四车必须让后端有四辆适配车辆、对应仓库订单、真实道路数据并重新求解；不能强迫最优求解器虚构四辆正在配送。
- 目前未补录 R24 业务细节、未自动部署 OSRM 及地区路网。保留 R24 业务补录流程，绝不伪造数据。
- 当前仓库还是 R24 几何示意模型。**R26** 再做可进入式冷库、货架、区域、叉车取货/运输/上架和装车操作事件。R27 再让仓储与车辆时间轴统一联动。
- API/PG 旧业务七表、六扩展表、R22 存档表、算法与冻结证据均不变。前端完整 `npm run build` 在当前隔离环境依赖安装无法完成，需由 Windows 运行验证；语法检查与专项 Node/后端用例不等于正式浏览器测试。
