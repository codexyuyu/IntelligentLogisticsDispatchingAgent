# R30-E｜异常处置与业务差异证据增强（组会版）

**基线：**R30-D 已由用户在 Windows 上确认正常运行。R30-E 原样继承已有 WH001 单现役仓库、R27 仓运联调、R28 对账、R30-B 四类异常、R30-C DeepSeek 接口和 R30-D 冷链审计。无数据库迁移、无正式业务写入、无新增外部系统依赖。**并非生产级异常派车系统。**

## 修改内容

1. 新增 `backend/app/adapters/persistence/pg_r30e_evidence.py`，从 **R30-B 原方案 + 已验证的异常事件流** 构造新旧差异：
   - 每单原车辆、新预计配送车辆、原/新预计送达秒数、变化量、未服务原因、是否真正受到异常影响。
   - 每辆车原订单顺序、**实际事件流中仍预计送达的订单**，以及是否在异常时刻被模拟停驶。故障车旧路线仅作为参考几何，不能算作新的交付承诺。
   - 仓储作业中断、未来取消、资源/时间重排及对应旧新资源、时刻。
   - 影响订单数、送达时刻变化单数、已服务重新指派订单数、仓储中断数。
2. 新旧结果必须和事件流逐单核对。若对外宣称的 `new_delivery_at_s` 与事件记录不符，抛出错误而不是产生误导性摘要。`new_plan_id` 包含异常类型、对象、时刻、延误秒数，避免不同延误预览共用同一版本标识。
3. 兼容保留原有 `comparison` 字段，新增 `impact_evidence` 作为独立证明。正常 R27/R28 和已有外部接口不需要改请求体。
4. `r30c/quick`、`r30c/chat` 的 `simulate_exception` 工具摘要新增受影响订单、车辆未来交付、仓储变动和证据范围；模型系统提示明确：**校验通过 ≠ 所有订单恢复 / 真实派车**。模型没有新 SQL 权限。
5. 仓运闭环异常面板新增订单变化和仓储中断明细；3D 回放继续使用同一个后端结果的 `baseline` 与 `replay`，修改文案避免把只读混合回放误认为新 R28 正式 Plan，并从实际事件提取装车就绪状态，避免将所有订单默认设为已就绪。

## Windows 上的最短启动步骤

1. **在全新文件夹解压 R30-E 完整 ZIP；不要覆盖已正常运行的 R30-D。** 先备份项目自有文件，本版不执行数据库 DDL/写操作。
2. 后端 PowerShell：

```powershell
cd backend
powershell -ExecutionPolicy Bypass -File .\start_pg_r30c_local.ps1 -DemoOnly
```

按原 R30-C 说明安全输入 DeepSeek API Key；不要将真实 Key 贴进聊天或提交到 ZIP。`-DemoOnly` 表示默认只选内置合成场景。需要 PostgreSQL 模式时使用原 R30-C/R30-D 已验收的启动配置，勿伪造源数据。

3. 前端新 PowerShell：

```powershell
cd frontend
npm ci
npm run build
npm run dev
```

打开 `http://127.0.0.1:5173` → 「智能调度」→ 「单仓仓运闭环」。

## 组会前最少要检查的 5 个场景

先计算正常 20 单联合调度，确认 `R28 passed`、仓储作业时间/车辆路线均有显示。之后分别模拟：

| 场景 | 检查要点 |
| --- | --- |
| V/veh 车辆故障 | 已完成订单不再次交付；故障车未来订单不是“已送达”；车上货物需已验证转运，否则未服务 |
| 在途配送延误 | 已完成交付不改变；可行时 `delivery_delta_s > 0`；时间窗不可行时明确标记未服务 |
| 仓储资源故障 | 发生前已完成作业不修改；受影响作业在 **仓储中断/取消/重排表** 中可见 |
| 库存批次隔离 | 不虚构替代库存；需要质量暂停/人工评估的货物清晰列出 |
| DeepSeek 与 3D | AI 的 `impact_counts`、`affected_order_details` 与同次工具 `artifact` 一致；跳转到 3D 比较原方案/异常预览不混入另一轮独立求解 |

如果需要最稳定的演示数据，首选 **合成单仓模式**。PostgreSQL 模式仍需 WH001、现有 R24/R27 表及本机数据；即使数据在 PostgreSQL，也可能标记为 `explicit_synthetic_demo`，不代表现场数据。

## 本次检查与限制

在当前隔离 Linux 环境对 R30-E、R30-B、R30-C、R30-D、R27、R28、R30-A/R24、R29、R26 的定向测试执行：**91 通过**（包含新增 R30-E 6 项）。使用历史验收记录、模拟 DeepSeek 和部分测试替身；**不是当前环境的真实 OR-Tools 后缀求解、PostgreSQL 实库和在线 DeepSeek 端到端验证**。Python 语法检查通过。

前端已用本包 TypeScript 执行类型检查，但完整检查 **受原包 `node_modules` 缺少 Linux 平台依赖/类型文件阻断**，错误集中于 `openapi-fetch`、`three`、`vite` 与其衍生类型；未观察到本次新增 TS 文件的独立错误。请在你的 Windows 上执行 `npm ci` 和 `npm run build` 作为最终确认。无正式 Windows R30-E 验收结论。

**业务限制：** 不接实时 GPS/天气/设备，不提供验证过的跨车辆现场转运；不做长期冷间占用、预冷、清洁换批优化，不进行正式方案确认/库存扣减，不在当前 3D 中逐秒还原真实物理车辆。局部不可行是允许结果，必须说明原因。保存旧版 R30-D ZIP 作为回退基线。
