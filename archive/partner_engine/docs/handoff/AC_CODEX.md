# 给用户侧 Codex：实现 A＋C 与前端

用户拥有 A＋C 并监督 B；先读 AGENTS.md、DEV_LOG.md 开头、OWNERSHIP.json、docs/NAMING.md。B 的算法/矩阵/仿真实现暂不改写。不要把 B 的未完成输出包装成已完成流程。

## 实现顺序

1. AC01：校验共享场景、仓储/库存对象；仓储独立规则、CP-SAT adapter。
2. AC02：FastAPI 业务路由接 use case，落数据库模型/迁移、快照与计算作业；HTTP只做边界转换。
3. AC03：在 bootstrap 注入 B 的 RoutingSolver、矩阵 provider 和 Simulator。B 未交付时用 tests/fakes 中显式替身测试协调；正式启动不能默认使用替身。
4. AC04：仓储就绪→运输→实际到达→仓储反馈，最多三轮共享预算；独立联合校验、快照版本和哈希。
5. AC05：确认事务，旧/新预留原子替换、并发/重复确认、旧版本拒绝、工作进程恢复。
6. AC06：异常影响、事实冻结、剩余任务重排，明确未支持的运行中故障。
7. AC07：模型有限意图/来源核对、确认、证据解释与失败降级；不用模型直接写库或提交确认。
8. FRONTEND01：全部页面由本侧 Codex 实现；复用生成的客户端类型。先联订单→计划→确认，再做异常对比和实验页。开发实现与业务状态分开展示。

你是公共契约集成维护者。B 的提案合并时统一升版本、更新 OpenAPI/TS、样例与双方调用。禁止只改一端然后在日志写“另一端自行适配”。日常私有实现无需额外审批。

每周按 ROADMAP 检查 B 的可运行交付：W1 约束反例、W2 仓库就绪约束、W3 异常剩余任务、W4 干净环境。监督通过输入/输出与独立反例进行，不用把全部 B 模块重写一遍。

完成每个任务写 docs/devlog/entries/，记录未完成/接口变更/测试结果，更新 FILE_MAP。四周最小版之后再启用合同网、自动换仓、跨仓转运、7 天预约和全量实验。
