# B模块算法前端演示说明

这次改造专门把成员 B 已完成的算法能力接到可操作的前端流程中。

## 你现在可以从哪里开始

进入 `frontend` 后启动 React，再启动 `backend`。打开首页「数字孪生驾驶舱」，顶部会看到 **B模块一键案例**。点击「开始完整案例」，系统会按真实 API 顺序执行：

1. 导入 `two_warehouses_20_orders.json` 的 20 单双仓案例。
2. 调用 `/api/v1/planning-jobs`，执行 OR-Tools CP-SAT 仓储排程 + OR-Tools Routing + B-03 仓运协同。
3. 注入 `veh_1` 在 900s 出发延误 900s 的已验证 B-04 异常。
4. 展示受影响订单、锁定订单、重排前后 Plan、求解状态和独立验证。
5. 调用 `/api/v1/simulations`，执行真实 SimPy 1800s 推演。

## 单独查看你的算法

- `仓储排程`：点击「运行 CP-SAT 排程」或重新运行，查看资源甘特图、仓库交接窗口和排程状态。
- `运输计划`：点击「运行 OR-Tools Routing」，查看车辆、载重、容积、停靠序列和返回时刻。
- `联合调度`：点击「运行仓运联合调度」，查看备货 → 装车 → 出发 → 配送 → 返回的闭环。
- `异常处置`：当前页面只把 `departure_delayed` 标为可实跑，避免把未完成的异常类型误认为已经实现。
- `仿真回放`：可修改异常发生时刻和延误时长，再运行 SimPy，并用时间轴和 3D 场景回放。
- `订单与库存`：异常重排后自动切换到新 Plan，订单详情会跟着新路线走。

## 比赛现场推荐操作

首页 → 「开始完整案例」 → 等基线生成 → 切到「联合调度」看仓运链路 → 切到「异常处置」看局部重排 → 切到「仿真回放」拖动时间轴回放 → 最后到「B-06 实验与证据」查看真实返回的实验对象。

## 环境要求

前端第一次启动建议重新执行 `npm ci`，不要复用其他操作系统带来的 `node_modules`。后端需要按 `../WINDOWS_SETUP.md` 安装 OR-Tools 9.15.6755 和 SimPy 4.1.1。
