## 要求分层

公开命题明确了路径规划、异常处置、仓配协同，以及作品简介、团队介绍、技术方案、视频和原型。日志与场景仿真数据在该物流题目下属于鼓励提交。本项目主动把它们纳入交付，便于证明成果。

申请书另承诺冷链、局部重排、SimPy 推演、四角色合同网协商、可复现实验。它们是本团队的研究范围，不宜声称全是竞赛统一硬要求。文中使用“等智能体开发平台”，用户也已明确不必接入万悟，因此平台适配是可选任务，大模型实际工具调用仍属于主线。

## 最小场景与边界

按三人、9 周开发加 1 周测试计划。基础场景设 2 个仓储节点、4 辆单温区车辆、20 个不可拆批订单、两类温区、1 天执行窗口；随后扩大到 50/100 单。另以小规模 7 天资源预约场景展示申请书中的跨批次顺序复用，避免把全天精细运输与七天大规模排程一次性塞进同一模型。数值都是工程起点，未经性能测试。

两仓必须共享一个协调流程：至少覆盖不同起始仓的配送订单，另设置“可选择接收仓”的入库任务。跨仓转运只在场景显式定义转运腿、交接时间和对应库存移动后启用。首版不支持任意多跳中转、动态拆单、多温舱混装；遇到这类要求返回明确的未支持状态。

货物异常以合成温度序列与明确阈值检测，异常批次转隔离状态；阈值来自带版本的场景规则，不能由模型推测。此版本不做食品安全鉴定。天气和路况使用版本化场景事件及行程时间变化，不宣称掌握实时道路情况。

## 申请书建议修订

| 原表达 | 建议表达及理由 |
| --- | --- |
| CP-SAT 统一承担路径规划与仓储 | 运输优先用 OR-Tools Routing，仓储用 CP-SAT，通过协调器衔接；小规模整体 CP-SAT 可作为后续研究对照 |
| 从机制上杜绝幻觉 | 约束抽取需来源与确认，计划需独立校验和版本检查，降低未经验证内容进入执行的风险 |
| 自动生成最优路线 | 在限定预算内生成并验证可行优化方案；仅对有证明的对应模型标注最优 |
| 局部重排显著缩短时间 | 作为待验证研究假设，通过相同事件和预算对照报告结果 |
| 数字孪生 | 初期称仿真驱动的数字孪生原型；尚未完成真实传感器同步与参数标定 |
| 保护经营数据 | 只交换必要字段并实施视图访问控制；不宣称已完成跨组织隐私安全证明 |

原 PDF 本轮未修改。这些修订保留研究方向，同时把承诺变成可验证的范围。
