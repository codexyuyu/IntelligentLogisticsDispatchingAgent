# 可手算验收数据与扩展场景规范

短ID仅作说明；实现时使用稳定UUID5。全部时间相对epoch=`2026-09-12T00:00:00Z`，整数秒；无特别说明所有资源在[0,3600)可用、订单必服务、单趟、固定温控4.0°C、初始配送货物在车起点仓库、已完成必要出库作业、无额外等待或费用。测试必须在各任务中局部声明变动字段，不能悄悄修改共有fixture期望。

## T1 运输正例

节点顺序D,A,B。distance_m=`[[0,3000,7000],[5000,0,2000],[4000,6000,0]]`；travel_s=`[[0,300,700],[500,0,200],[400,600,0]]`。非对称有意设计，非对角不可达用null，不用0。

O1:D→A，O2:D→B；各weight=400000g、volume=1000000cm³、quantity=1、temp=[20,80]decic；各delivery service=60s；O1开始窗[0,600]、O2开始窗[0,1200]；soft_due分别360/620。V1 start=end=D，capacity_weight=800000g、capacity_volume=2000000cm³，setpoint=40，司机S1 shift[0,3600] max_drive=3600 max_work=3600，rate=100分/km、fixed=500分，出发t0，仓库装车已结束于t0。

唯一最低距离路线D-A-B-D：距离9000m；A arrival/start=300,depart=360；B arrival/start=560,depart=620；回仓t1020；行驶900s、服务120s；逐段实际载荷800000→400000→0g；成本900+500=1400分。独立回算全部字段，不能只比求解status。反向路线18000m且时间窗失败。载重改799999而仍必服务、单趟→不可行；容积改1999999同理。A窗改[350,350]→A到300、服务350..410、B到610、服务到670、回仓1070。再令B硬latest_start=600→不可行。后一个负例基于A固定350变体，不能脱离变体误判。

冷冻C1温区[-250,-180]与上述冷藏同固定温控车不可同运；增加独立冷冻车可分车。T1 solver基础阶段尚未集成所有约束时，只对当前已实现边界宣称通过；G07必须包含全部约束。

## W1 仓储正例

H1、固定温控40、D1月台一台、worker pool容量2、sorting设备E1容量1、handling设备E2容量1。任务A duration10、B duration10，B依赖A；两任务占同D1和1名worker；窗口[0,100]。A类raw、B类clean，SetupPolicy raw→clean=5s，需要同D1及1名worker。初始月台class=raw，初始切换0；末尾切换0。

无setup规则变体：A[0,10)、B[10,20)，makespan20。完整规则：A[0,10)、setup[10,15)、B[15,25)，makespan25。未显式更改时使用完整规则。独立验证可允许整体合法平移，但优化最小makespan例要求从0开始。两个任务分别需2worker且池容量2→不能重叠；设备停机[5,15)使任何与其重叠且需该设备的作业非法。

库存S1：温区容量10单位、初始8单位保持[0,20)，新3单位在t10入库→t10..20超容；新3单位在t20入库→可行。正式字段需同时提供对应weight/volume，测试可设每单位1000g/1000cm³，两维容量均10000。

## J1 仓运交接反例

## I1 影响与故障

任务图T1→T2（同一实物链），T3使用另一车/另一月台、不共享重叠时段；事件为T1车故障。最小影响闭包{T1,T2}，T3资源/时间/顺序完全冻结。T1的车辆在D→A路段t150故障，位置为该路段1/2，剩余配送货物800000g。救援实例额外给RV1当前位置与到故障点travel=120s，交接60s、容量800000g、温控40、交接最大暴露120s；最早完成交接t330。无这些数据的变体必须MANUAL_REQUIRED，不能自行发明救援道路或时长。

取消测试独立运行：装车前取消释放未来交付预留；在途取消100箱仍有100箱返仓或显式处置任务；已交付取消不能改历史。需求增加必须重新核算重量/容积/数量，需求减少不允许降到已交付数以下。天气time100×3/2=150（向上取整），距离不变，旧矩阵和已走路段事实不变。

## S1 仿真恢复

用T1无扰动，t400处于A→B，t1020终态。连续运行与t400快照恢复结果相同，比较规范化事实序列、库存、终态hash和指标，排除wall-time和新分支ID。故障t10和completion t10排序按故障优先。两次相同source/event_id应用只产生一次状态变化；fork后修改天气不改变原分支hash。

## M1 指标

有效需求5，交付4，按时3，已交付延误[0,0,0,40]秒→0.8/0.6/10秒；两车busy60/30，可用100/100→0.45；四未来任务仅一项改派→changed=1、disturbance=0.1；V1 cost1000、V2 cost1200→added_cost200。无分母返回null+reason。

## A/B/C 扩展Demo生成参数

所有实例source=synthetic，seed42，epoch同T1；完整节点矩阵由生成器产出并保存，不在实现中硬编码最终解。节点可取网格坐标，仅用于示意；生成距离=`1000*(|dx|+|dy|)`，time=`ceil(distance/10)`，说明这是合成道路矩阵。出发仓D1=(0,0)，D2=(10,0)，客户顺序按i生成(x=i%5+1,y=i//5+1)并保证不同ID可同位置但明确服务点不同；同位置不同点行驶0只在显式connected arc允许。horizon=28800，客户开始窗[0,24000]，每单service60、weight100000、volume1000000、quantity1；soft_due=20000。

Scenario A：D1一个仓、8单，前4冷藏[20,80]、后4冷冻[-250,-180]；2车分别setpoint40/-200、容量1000000g/10000000cm³，各自司机全天班，装车任务t0已结束用于纯运输展示。每车单趟，必须8/8交付。

Scenario B：2仓4车20单，每仓10单（各5冷藏/5冷冻），每仓两固定温区、每区容量2000000g/20000000cm³；每仓1月台、2worker、sorting1、handling1；4车每仓冷藏/冷冻各1，容量1000000g/10000000cm³。每单流程unload60→receive30→sort60→dispatch30→load60；出入库台共用D，sort需sorting和worker，装卸需handling与worker；温区切换setup30秒，初始温区40。货物作为外部入库arrival0的显式来源，不能与初始已入库重复计算；初始库存0。输出真实完整联合解、资源甘特及指标。

C1/C2/C3各从通过验证的B分支启动独立试验；不能固定假设t150车辆一定已发车。C1先推进选定车辆实际departure+150，注入位置/救援字段（I1的t150只是小fixture），C2分别在目标货物load前与实际departure+150取消，C3在首个已发车但有未来路段时刻注入天气。C1/C3要保留足够备用资源与时间窗裕量，增设明确RV1救援车，不隐性超卖容量。每个演示保存原方案、异常、影响范围、候选方案、新方案、六项diff、指标变化；接受失败演示必须标失败，成功演示必须有完整硬约束验证。
