# 契约变更验收入口 · contracts/changes

本目录是**公共契约变更的唯一验收入口**。依据 `docs/architecture/DATA_CONTRACTS.md`（变更规则）与架构约束第 5 条：先写变更说明，再按固定顺序迁移；生成物只能由生成器重写。

本文件由任务 `P01-03` 建立，只定义**格式与验收标准**，不登记任何具体变更。

## 1. 什么时候必须写

下列任一项成立即必须新增一份变更说明（`contracts/changes/CHG-NNNN-<slug>.md`），不接受只改代码或只在聊天里说明：

- 破坏性变更：字段改名/删除、单位改变、enum 成员增删改、路径改变、必需语义改变（升 **major**）；
- 新增可选字段（升 **minor**）；
- 兼容性修复（升 **patch**）但不改变对外语义；
- 任何需要重新导出 `contracts/schemas.json` / `contracts/openapi.json` / `apps/frontend/src/client/generated.ts` 的改动。

## 2. 每条变更必须回答的字段

| 字段 | 必填 | 内容要求 |
| --- | --- | --- |
| `schema_version` | 是 | 本说明格式版本，当前 `1.0.0` |
| `id` | 是 | `CHG-NNNN`，唯一且不复用 |
| `task_id` / `owner` | 是 | 发起变更的任务与责任方（`A`/`B`，由 `scripts/check_ownership.py` 判定） |
| `change_class` | 是 | `breaking` / `additive` / `fix`，对应 major/minor/patch |
| `契约版本（前 → 后）` | 是 | 例如 `1.0.0 → 1.1.0` |
| **输入影响** | 是 | 受影响的输入字段/单位/enum/路径，逐条列出；写明旧值、新值与是否必需 |
| **输出影响** | 是 | 受影响的输出/结果字段、错误码、状态语义；写明 `SolveStatus`/`JobStatus` 等是否变化 |
| `受影响调用方` | 是 | 逐条列出需要同步修改的模块、测试、导出物（含前端生成客户端） |
| **迁移顺序** | 是 | 固定为 `domain → DTO → ports → 调用方 → 测试 → 生成物`；写明每步实际文件 |
| 生成物处理 | 是 | 明确哪些导出物需重跑生成器；**生成物禁止手改** |
| 校验引用 | 是 | 变更后的 `version_id`、`parent_version_id`、`snapshot_hash` 由哪个任务的哪个校验产出 |
| 兼容性/回滚 | 是 | 是否兼容旧输入；旧数据如何转换；失败时如何回退 |
| 证据 | 是 | 命令、日志路径、退出码；未执行项必须显式写出 |

## 3. 验收标准（缺一不可）

1. 说明文件存在且上表字段齐备（`scripts/check_ownership.py` 会检查关键字段是否被文档化）。
2. 变更顺序按第 2 节执行完毕，受影响调用方与测试在同一变更内更新。
3. 生成物由生成器重写，且 `--check` 模式无漂移。
4. 受影响 Gate 的证据已重跑并重新记录（旧证据因公共契约变更而失效，不能只改日期）。
5. 非阻断的架构问题按 `docs/architecture/issues/README.md` 登记并继续限定任务；阻断问题只做最小契约迁移，禁止大规模重构。

## 4. 与所有权判定的关系

变更涉及的路径必须能由 `scripts/check_ownership.py` 解析出唯一 owner；跨 B 范围的契约变更不得由 A 单方面改 B 的实现。若变更需要 B 的模块配合，先在同一说明中写明分工与交接路径，再各自在自身范围实施。
