## 共享工作必须有边界

- A 定数据库迁移规范，B/C 各写本域表和访问实现；A 不包办所有数据库工作。
- B 提供事件时钟和回放驱动，A 实现仓库故障/库存事件处理，C 实现影响集与重排触发；B 不包办所有异常业务。
- C 维护联合校验入口，A 写库存/资源规则，B 写运输/时间链规则。A→B→C→A 循环互审，求解器和校验器不能共用同一段判断实现。
- C 维护作业提交/查询，A 维护正式确认与资源预留；两者用计划 ID、快照版本、校验报告交接。
- 每人维护本方向实验数据和章节；C 汇总证据索引，视频脚本和最终答辩由全员核对。
- 集成值班逐周 A→B→C 轮换，每人预留约 20% 时间联调和修复。谁值班只负责定位/协调，不替所有人修模块。

## 可以独立开发的交换约定

| 提供方→使用方 | 输入/输出 | 隔离要求 |
| --- | --- | --- |
| A→C | 仓储快照、作业、可用日历 → 排程/冲突/货物就绪时间 | 不输出 CP-SAT 变量或数据库对象 |
| B→C | 车辆、订单、时间矩阵、就绪时间 → 路线/服务时间/未服务原因 | 不自行改订单或正式库存 |
| C→A/B | 固定快照、候选范围、剩余预算 → 结构化求解请求 | 最多 3 轮反馈，不能无限互调 |
| B→C/A | 带事件 ID/时刻/来源的仿真事件 | 仿真事实不直接写入正式执行记录 |
| 三人→Codex | OpenAPI、样例 JSON、错误码与状态含义 | Codex 生成前端；三人只确认业务展示正确 |

第一周先共享最小输入/输出样例。A/B 可各用文件快照，C 可用假求解器验证状态流程；第 3 周切换真实适配器完成联调。正式单位与接口以 [契约文档](04-contracts.md) 为准；今日 demo 的分钟单位仅用于教学，迁移时明确转换成秒。

## 每人的独立验收与成果

| 人员 | 必须演示的成功与失败 | 可用于竞赛的个人贡献 |
| --- | --- | --- |
| A | 可行排程；月台冲突/隔离库存/过期预留被拒绝；两请求争最后资源只有一次确认 | 仓内多资源建模、预留一致性、资源紧张下的对照 |
| B | 两类温区车辆服务订单；超载/迟到被拒绝；固定种子事件回放可复现 | 路径优化、状态推进、规模与时间预算实验 |
| C | 需求草案可核对；错误候选不能确认；异常后保留事实并有界重排；模型故障可降级 | 仓运协调、异常影响分析、证据约束与语义错误评测 |

每人每周至少交付一个可复现小案例及一条反例。今日三个 demo 是起步材料，不代表上述完整能力已实现。完整周计划见 [路线](06-roadmap.md)。
