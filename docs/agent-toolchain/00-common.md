- 所有工具名称、参数、配置路径和版本以本机 help、对应版本源码/官方文档为准。检查只能读取必要字段，凭据只记录“存在/缺失/可用”，不输出其内容。

## 插件与环境

- 区分 Skills、MCP 服务、宿主原生插件、CLI 工具、浏览器扩展；不能互换安装格式。共用技能需检查路径、脚本、权限和工具名映射；共用 MCP 需检查 stdio/HTTP、认证、工具 schema 与超时；原生 hooks/API 逐宿主适配。
- 先盘点用户级、项目级、profile、缓存、自动发现目录及实际生效配置，再决定安装。等效能力已可用时复用，尤其是浏览器、搜索、记忆、review 和编排器。
- 查询官方文档、源码仓库、发布说明、包注册表。记录精确版本、来源、发布日期、engines/peerDependencies、许可证、所需外部服务与费用；无证据记 UNKNOWN。
- 优先当前受支持版本的正式发布通道；只有预发布的项目如 DSH 要如实标注。`latest`、`next` 与 `beta` 只是可变标签，不能直接等同于稳定性。
- 先备份，再在可验证的隔离配置与临时项目测试；同一时刻只变更一个能力组。不要把 agent 工具依赖装进物流应用依赖中，除非它本来就是应用要求的测试工具。
- 保留用户原有模型供应商、登录方式与插件配置。不得为了试验新插件迁移用户的认证渠道、开启新的付费服务或清空现有配置。
- 通过验证的本地依赖固定精确版本/commit，并保存原有包管理器的锁文件。远程服务只能记录端点、协议和验收时间；不要编造固定服务端版本。
- Windows 上核验原生依赖、PowerShell 转义、Unicode/空格路径、Node/Bun/Python 版本和进程退出。启动后台辅助进程时隐藏窗口；只管理本任务启动或明确识别的进程，不结束所有 Node/Python 进程。
- MCP 探针至少包括初始化、列工具、一次合法调用、一个错误输入、取消/超时和重启。浏览器测试用临时 profile；数据库测试用隔离测试库。安装成功不等于兼容性通过。

## 开发与交接

- WorkBuddy 仅用于免费额度内的简单任务，不担任总调度、架构裁决、Gate 签收或关键业务实现者；其不可用不阻塞主流程。
- 同一任务同一时刻只有一个主写者。并行只用于依赖已满足、路径不重叠的任务，并记录各自工作目录、数据和端口。
- 发现依赖阻塞后沿 DAG 找最早可修复节点，交还调度者生成限定修复任务；根因和输入 hash 未变化时，不重复运行整套必败命令或制造下游阻塞报告。
- 不把空目录检查通过、零测试、跳过集成测试或输出文档数量增加当作业务实现通过。测试替身不能替代需要真实 PostgreSQL 事务/锁/并发语义的验收。
- 测试不得依赖活跃工作区中“某审查记录永远缺失”。失败关闭的正反例在受控临时仓库设置输入；正式记录必须在调用前后比较，不能删除真实审查记录来满足测试。
- 未签收 Gate 的自检不能授权下一阶段。`--check-only` 不写签收记录；即使退出 0，也要确认官方 Gate 存在、passed、所需字段/输入/日志/依赖有效，防止把“没有记录可检查”理解成成功。
- 物流业务坚持确定性求解、独立硬约束校验、数据版本校验与事务提交；LLM 解释不构成可执行调度方案的正确性证据。
- 审查者使用新会话与候选快照；如果审查中修改候选，记录新 revision 并重新验收受影响部分。变更量小且低风险时避免重复全量测试，但必须完成项目规定的 Gate。
- A/B 是实际所有权，agent 分工不能覆盖它。跨所有者或公共契约变更遵循现有治理；不要靠悄改白名单、放宽断言或伪造证据解除阻塞。

## 每次交付

环境任务输出：宿主与运行时、已声明/已安装/已加载/已验证插件列表、改动、精确版本、探针结果、失败项、恢复方式。写到 `artifacts/toolchain/<日期>/<agent>/`，避免保存原始机密配置。

开发任务沿用项目 `docs/handoffs/<task>/<agent>.md` 与 `artifacts/handoffs/<task>/<agent>/`，记录 task、owner、输入候选、模型/宿主/插件版本、文件范围、真实命令/退出码、测试数量、日志路径/hash、阻塞根因和下一执行者。只补缺失字段，不无谓创建第二套任务状态来源。

实现者只能写自己的交接与临时 Gate 探针，不能冒签 ZCode/Codex。审查者的输入哈希须非空且覆盖必要输入；输出记录与日志保存独立 hash，不纳入实现候选而造成自引用。公共文件变更后的旧通过结论必须重新验收，不能只更新 hash。

状态分清 `PASSED`、`FAILED`、`BLOCKED`、`NOT_RUN`；工具或网络不可用就报告事实。常规可逆配置和已授权的工作直接推进；只有需要新账号/付费授权、用户交互登录、打断活跃任务或其他缺失的必要条件时，完成独立准备工作后再提出一个具体请求。
