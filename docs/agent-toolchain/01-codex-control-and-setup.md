# 给 Codex：主流程盘点、环境去重与最早阻塞点

请为当前项目建立可靠的多 agent 开发入口，并配置 Codex 缺失的必要能力。先读同目录 `00-common.md` 和 `README.md`，遵循适用项目规则。这个任务负责环境与调度准备，不自动执行其他 agent 的提示词，不自动改业务代码或签收 Gate。

1. 确认真实项目根和迁移状态。读取当前 manifest、Gate、所有权和最新交接，指出 README/计划/实物不一致的地方。输出一页当前事实；不沿用文档中“尚未实现”或“已完成”的旧文字作为唯一依据。
2. 只读盘点 Codex、OpenCode、DSH、ZCode、pi 的安装渠道、实际入口、版本、运行时和可用模型路由。Codex 桌面与 CLI 分开；记录已安装不等于已加载。WorkBuddy 仅记录能否领取简单任务，跳过其深度配置。
3. 检查当前已有的官方文档、浏览器、GitHub、Security 等工具/skills。复用可用能力；确有缺口才配置官方文档入口、Context7 或一个浏览器通道。GitHub 尚未接通实际仓库时不为它创建账号或上传项目。使用当前界面/CLI 支持的插件机制，不手写假定的市场安装命令。
4. 对共用技能建立“源内容 + 宿主适配说明”，不要未经验证把各 agent 配置目录硬链接在一起。记录 Codex 插件在 CLI/桌面是否分别可见，重开会话后再确认。
5. 建立最小工具版本清单：host、host_version、runtime、plugin_kind、package/source、精确版本/commit、scope、声明状态、加载状态、功能验证状态、rollback、verified_at。机密字段用引用；远程服务注明不可锁服务端版本。优先复用已有清单；否则写 `artifacts/toolchain/<日期>/codex/`。
6. 从最早未通过 Gate 反查可执行前置任务。当前历史观察是 G01 failed，后续 P02–P05 已有连锁 BLOCKED；重新核实后只选一个最早修复任务。为该任务给出真实 owner、文件白名单、输入候选和能够通过的验收条件。
7. 如果白名单、接口归属或依赖图本身有矛盾，按项目架构治理形成一个最小修复任务，包含受影响契约/调用方/测试/生成物，不以越权改动或永远转圈的 BLOCKED 报告替代解决方案。任务书需要的权限由已授权 owner 流程确认，agent 品牌不能提供额外所有权。
8. 保留既有 DSH→ZCode→Codex 证据链。OpenCode 可被指定为某个任务的唯一实现者，但不得让它冒充 DSH 签名；如果现有 Gate 硬编码角色，先通过治理更新映射，再分配备用实现通道。

交付：环境盘点、最小能力变更及验证、可恢复版本记录、当前唯一任务卡和下一位 agent 可直接复制的启动文本。明确哪些工具/模型尚未实测，不给无数据的绝对实力排名。需要升级 DSH 时引导执行 `03-dsh-upgrade.md`，不在此任务顺手升级所有工具。
