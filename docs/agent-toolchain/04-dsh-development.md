# 给 DSH：实现一个已具备前置条件的任务

请作为本项目的实现 agent，完成调度者提供的一个任务。先读同目录 `00-common.md`，再读任务对应的 `docs/prompts/` 文件、manifest、所有权与当前交接。任务 ID 以本次用户/任务卡为准；未提供时，只定位最早可执行任务并生成任务卡，不直接跳到最新编号。

2026-10-01 当前入口：先读根 `AGENTS.md` 和 [返工后完整派发](12-project-completion-dispatch.md)。P01-02 的四项限定返工已 READY_FOR_ZCODE 并停写；无新缺陷卡不得重启旧返工。G00 解阻后只按 N03 刷新自身 Phase 01 交接，交 ZCode 独立预验收；G01 有效前不得开始 P02 或重复 P03–P05 阻塞轮次。精确任务卡范围优先于通用实现范围。

## 开始前

1. 检查实际 DSH、模型路由、profile、已加载工具与插件版本。只检查本任务需要的文件编辑、命令执行、搜索/文档能力，不在实现期间升级 DSH 或整个插件环境。
2. 读取并核验前置 Gate 与同一候选的证据；区分记录中的 passed 与当前内容已变化导致证据失效。核对 owner 和文件白名单，不改 B 的模块来掩盖 A 的接口问题，反之亦然。
3. 如缺失前置，沿 DAG 找出最早失败节点，提供一个最小修复建议与下一执行者。根因和输入未变时不要重复跑下游必败任务。已经处于 BLOCKED 的 P05 任务不能靠继续新建报告变成完成。
4. 如果发现本任务负责某类型却没有合法落点，按项目治理提交最小契约修复任务；不要创造未定义 dict、复制公共类型或手改生成物。
5. manifest 的初始状态不是当前执行状态。前置记录必须核验内容、非空且足够的输入哈希、原始日志和真实退出码；只写着 passed 或 `--check-only` 退出 0 不足以授权下游。

## 实现

- 你是本任务唯一主写者；OpenCode/WorkBuddy 的候选补丁先核对输入快照后再决定是否采用。
- 在真实文件中实现任务要求，重用冻结契约。边界参数、版本、错误、超时、取消与幂等语义必须明确。不要为了“可运行”接入与正式规则不同的假求解器或假数据库。
- 复杂代码先复现问题或建立有业务意义的断言，再实现；简单文案/可逆低影响修改按实际风险验证，不为流程凑测试。
- 求解结果由独立校验器核验；未知、超时、不可行、过期必须保留真实状态。模型生成的解释不替代计算与事务证据。
- agent-teams、memory、浏览器等只在本任务有明确收益时启用；外部记忆必须附项目、task、revision 和来源，不能覆盖本地契约。避免多个团队循环重复分发同一任务。

## 验收与交接

运行任务要求的命令和必要回归，记录收集/通过/失败/跳过数量与退出码。需要 PostgreSQL 并发语义时使用真实隔离测试库。零测试、空目录扫描和只运行旧用例不能证明本任务完成。

冻结代码与契约候选，记录固定输入文件集/hash；交接报告和日志不进入导致自身变化的 hash 范围。按现有 schema 写 `docs/handoffs/<task>/dsh.md` 与 `artifacts/handoffs/<task>/dsh/`，列出变更、验证、剩余限制、需要 ZCode 特别复核的边界。DSH 不签署 ZCode 预验收或 Codex Gate 审查结果。

先写实际产物和日志，再复算文件存在数量与 hash；不能把预计写出的文件算作已存在。保留旧轮日志与证据，不能从旧记录复制 hash 后冒称重验。DSH 的 Gate 探针只写 `tmp/<task>/...`，不覆盖 `artifacts/gates/` 的官方记录，也不生成任何其他角色的通过文件。

交付后停止修改该候选，等待缺陷单。如果继续修复，生成新候选标识并通知审查者旧证据失效。
