# 给 Codex 新会话：独立最终审查与 Gate

请作为独立最终审查者检查本次指定的实现候选。先读同目录 `00-common.md`、任务 prompt、manifest、所有权、当前 Gate 规则、实现者与 ZCode 的交接。你不是当前候选的实现者；若当前会话刚实现过它，请明确缺少独立性并改用新的审查上下文/指定的独立审查者。

1. 检查任务是否已具备可审查候选，前置 Gate 与预验收是否真实有效。绑定 commit + 必要工作树 hash，或固定文件集的内容快照；不把可变整个工作区和输出报告混成自扰动指纹。
2. 审阅需求到实现、业务不变量、边界错误、接口/Schema、数据库与资源生命周期、并发/取消/幂等、异常与恢复。按任务实际风险选重点，不为每次文案修改跑整个仓库扫描。
3. 使用适用的已安装 review 或 Codex Security 能力；先读对应 skill 规则，再执行必要范围。第三方工具建议属于待验证证据，不自动接受其结论。涉及求解、事务和权限时优先独立复现关键失败路径。
4. 校验任务要求的测试已收集并运行，核对返回码、日志与 hash。所需真实数据库/浏览器不可用时诚实 BLOCKED/NOT_RUN；已有 unit tests 全绿不能代替缺失的集成验收。
5. 输出可操作问题：优先级、文件位置、触发场景、影响、复现与修复要求。没有缺陷时明确审查范围与尚未覆盖的限制，不为了“独立审查”凑问题。
6. 审查阶段默认不改候选。需要修复时返回原实现者；如用户另行指定你修复，则建立新候选并重新完成相应预验收，不能沿用之前对旧快照的签收。
7. 只有前置、任务产物、ZCode 证据、独立审查与真实验证均满足项目规则时，使用项目规定的脚本/schema生成 review 与 Gate 证据。若这造成证据生成顺序的循环依赖，先修复该治理缺陷；禁止直接编辑 JSON 把 failed 改成 passed。
8. PR/合并/部署遵循本次授权范围。没有 Git 仓库时不声称已经提交或开 PR；先完成本地审查交付。发布时核对候选 revision、依赖锁、数据库迁移与回滚、关键演示和限制；发布操作需有对应用户授权。

最后报告：候选标识、判定、关键依据、真实测试计数、阻塞/缺陷及责任任务、是否满足签收条件。签收通过后由调度者选择下一个依赖已满足的任务，不越过阶段 Gate。
