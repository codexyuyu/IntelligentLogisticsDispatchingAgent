核查日期：2026-10-14。任务：[DATA-PREP-20261014](DATA-PREP-20261014.md)。

结论：保留 PostgreSQL 作为正式业务存储，先使用小规模合成输入；真实评估再分任务导入有许可的仓储、配送和路网数据。当前资料不要求独立图数据库。数据包不能消除领域模型、迁移、服务和求解器尚未实现的阻塞，也不能证明所有竞赛环境已满足。

## 2. 实际需要的存储

| 存储 | 作用 | 本次决定 |
| --- | --- | --- |
| PostgreSQL | 订单/资源、版本、库存、预留、任务、事件、审计、实验 | 正式主库；独立测试库与演示库必须隔离，不能等真实数据到来才测试 PostgreSQL |
| JSON/CSV + 文件目录 | 输入快照、矩阵、原始数据、日志、数据许可 | 随包保留，可哈希、可复现，不要求另建对象存储服务 |
| 图结构 | 工序依赖、仓库导航、道路连接、订单与资源影响关系 | 本次提供节点/边与可选 Cypher；主库仍是事实来源 |
| Neo4j 等独立图数据库 | 当关系遍历规模和独立图查询确有需求时作为投影 | 可选；尚无比赛强制证据，也未做实际导入验收 |
| 向量库/Redis/时序库 | 可选检索、缓存、遥测扩展 | 当前报告未要求；不增加为启动依赖 |

关系表和递归查询可以表达图遍历，见 [PostgreSQL 17 官方 WITH RECURSIVE 文档](https://www.postgresql.org/docs/17/queries-with.html)。使用图算法并不等于必须使用图数据库。若后续加入 Neo4j，用同一 UUID、快照版本与数据哈希生成只读投影；禁止 PostgreSQL/Neo4j 双主写入。

## 3. 本次小规模数据的用途

数据包位于 [data/preparation/competition-2026](../../data/preparation/competition-2026/README.md)。以 [TEST_FIXTURES](../plan/TEST_FIXTURES.md) 为输入依据，准备 T1 两单、A 八单、B 二十单、W1 手算案例与 C1/C2/C3 事件模板，包含仓运资源、整数单位、日历、矩阵及工序关系。

所有数值标为 synthetic。preparation Schema 是中间数据格式，尚未获得正式 DTO 验证；未定义的品类、人员技能等不冒充已冻结枚举。SQLite 仅用于现在打开数据与检查关系，不能用于 G03/G04 的 PostgreSQL 验收。PostgreSQL staging SQL 是数据暂存导入，不是正式业务迁移；32 实体覆盖清单也不等于 32 张业务表已实现。

路线、已提交调度版本、优化结果、仿真快照、处置结论和实验指标应由实际运行产生，不能为了“每张表有数据”预填成功记录。C 类模板需在合法 B 方案执行至对应时刻后绑定车辆、位置与事件，不固定猜测 t150 已发车。

## 4. 可信真实数据候选

以下是核实来源后的选择，不代表已下载、已导入或已经组委会认定合规。

| 数据集 | 真实程度与可覆盖字段 | 许可及采用条件 | 缺口 |
| --- | --- | --- | --- |
| [Mendeley 鞋厂仓储 V1](https://data.mendeley.com/datasets/pf2w725pw3/1)，DOI 10.17632/pf2w725pw3.1，2024-12-24 | 来自真实 WMS，经匿名化及随机化；订单、商品、库位、拣选波次和布局 | 数据页 CC BY 4.0；优先仓储候选，保留署名、版本及改动说明 | 不是冷链温控实测数据；不直接证明月台/司机/车辆约束 |
| [OpenStreetMap](https://www.openstreetmap.org/copyright)，[Geofabrik 中国入口](https://download.geofabrik.de/asia/china.html) | 实际地图道路节点与连接关系 | ODbL 1.0；保留署名，派生数据库再分发按许可证执行 | 非订单、非实测交通速度；速度估计应标 derived/modelled |
| [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online%2Bretail)，DOI 10.24432/C5BW33 | 真实销售明细，可用于订单导入、需求与 SKU 关系 | CC BY 4.0；作为辅助订单数据 | 无配送坐标、货物重量/体积、车辆和库位；价格为英镑，不能直接当人民币分 |
| [Amazon Last Mile 2021](https://registry.opendata.aws/amazon-last-mile-challenges/)，[字段说明](https://raw.githubusercontent.com/MIT-CAVE/rc-cli/main/templates/data_structures.md) | 脱敏真实配送路线、站点、包裹、服务时间、行程时间矩阵、执行顺序 | CC BY-NC 4.0；仅在非商业用途与提交条款相容时采用，不能承诺任意竞赛和商业发布均可用 | 缺完整仓储、冷链温控、货物重量；优先用其原始矩阵 |
| [菜鸟 LaDe 数据卡](https://huggingface.co/datasets/Cainiao-AI/LaDe)，[作者论文](https://arxiv.org/html/2306.10675) | 真实取派事件、配送员、AOI、轨迹 | 数据卡 Apache-2.0 与论文 CC BY-NC 4.0 有冲突；暂缓作为可自由再发布数据，需作者澄清 | 坐标不能未经验证直接当 WGS84；仍缺仓储与冷链字段 |

优先顺序：仓储评估用 Mendeley，真实道路结构用 OSM，订单导入用 UCI；配送路线评估在确认 NC 用途后用 Amazon。不同数据独立做实验。英国零售订单、鞋厂仓库、中国路网没有天然业务关联；拼接演示必须标记为跨源模拟，不能称为同一企业真实供应链。

没有找到同时包含真实订单、冷链温控、仓储工序、道路、车辆故障与全部成本的开放数据集。缺失字段应列入 assumptions 并做敏感性实验；不得补造后将整套记录标为 real。

## 5. 从合成到真实数据的接入契约

每批数据至少保存：dataset_id、来源 URL/DOI、发布版本、获取 UTC 时间、许可 URL、原文件 SHA-256、转换脚本版本、单位/坐标系、过滤条件、字段来源和缺失字段处理。

1. raw 保留原文件；normalized 保留转换结果；场景构造产生独立 scenario；不能覆盖 raw。
2. 实测值标 observed，单位转换/路径推算标 derived，补充值标 synthetic_assumption。温区、重量、车辆能力、准备时间逐字段记录。
3. 小样本按完整订单、完整波次或完整路线抽取，保留引用闭包和全矩阵；不能随便截前 N 行。
4. UUID5 由来源 namespace、原始实体 ID 与类型确定；保留来源映射，不以客户个人信息作为显示 ID。
5. 时区、温标、质量、体积、币种显式转换。矩阵节点顺序固定；不可达为 null，不用 0 代替。不同坐标系未经验证不融合。
6. 真实测试按时间/路线/订单组隔离开发与测试集，固定预算和随机种子；失败样本保留。仿真结果标 simulation，不冒充企业实绩。
7. 领域 Schema 完成后建立 preparation→正式 DTO 适配，再运行真实 PostgreSQL 导入和回滚验证；不得直接把 payload JSONB 当完整业务模型。

## 6. 数据库环境与恢复路径

提供独立 [Compose 配置](../../deploy/data-preparation-2026/compose.yaml)：PostgreSQL 17、127.0.0.1:55432、独立 logistics_prep_test 与专用数据卷。该选型为开发建议，不是比赛指定版本；赛前需记录镜像 digest 并在目标机复现。[官方镜像说明](https://hub.docker.com/_/postgres)。

本次 `docker compose config --quiet` 已通过；`docker info` 不能连接 Docker Desktop Linux engine，PATH 无 psql/pg_ctl，TEST_DATABASE_URL 未设置。尝试启动已安装的 Docker Desktop 后仍不可达。实际 PostgreSQL 导入、事务和并发测试未运行；详见 [环境探针](../../tmp/DATA-PREP-20261014/environment.json)。

Docker 引擎恢复后，在项目根执行：

```powershell
# 先通过本机安全方式设置环境变量 LOGISTICS_PREP_PASSWORD；不要提交密码。
docker compose -f deploy/data-preparation-2026/compose.yaml up -d --wait
docker compose -f deploy/data-preparation-2026/compose.yaml exec -T postgres psql -U logistics_prep -d logistics_prep_test -c "SELECT version();"
```

按数据包 README 导入 staging SQL，两次导入检查行数不增长，并验证无效外键导致事务失败。停止用 `docker compose -f deploy/data-preparation-2026/compose.yaml stop`，保留卷；首次初始化后不要误以为改环境密码会修改现有卷中的账号密码。

正式工程的恢复顺序仍为：裁定 P02-02 缺失类型 → P02 领域交付及 G02 → P03 真实数据库迁移/事务及 G03 → P04 正式数据导入及 G04。本次准备包不修改这些 Gate 的状态。
