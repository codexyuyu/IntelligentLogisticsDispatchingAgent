# 明日答辩：调度效果对比与 AI 决策证据（2026-10-31）

## 本轮功能

- **异常处置**：当前运行登记模拟车辆延误后，展示三列指标卡——原计划 v0、异常后简单顺延、OR-Tools 候选；综合费用、距离、迟到单数、累计迟到、预计配送数量。卡片只读取服务端持久化 `incident.comparison`，无演示硬编码金额。公平比较是 `candidate` 与 `simple_hold`；不能拿异常前 v0 宣称省钱。
- **仿真回放**：回放页在控制器上方直接展示同一组服务端指标，原明细保留在折叠面板。切换四车演示模式时隐藏该业务指标，避免把展示轨迹混入真实调度指标。
- **调度助手 / 调度指令**：对于延误任务，复用三列指标；对于没有可比基线的全量联合求解只报告实际求解指标，明确禁止宣称改善率。
- **AI 决策证据**：调度指令与异常处置复用三段证据卡，区分 DeepSeek 意图解析、后端 OR-Tools 求解校验、DeepSeek 解释和人工审批；显示实际分析审计 ID、运行 ID、模型状态及已发生的服务端工具核对记录，未配置/失败时明确提示非 AI 解释。
- **业务问答**：增加模型回复状态、实际只读工具调用次数和审计编号的证据摘要，保留原详细原始记录。
- **旧功能**：完整保留广西科技大学文昌校区二维地图、轨迹动画修复、单仓 3D、数据库接口、人工审批、DeepSeek 后端逻辑。

## 口径与限制

- 后端比较范围固定 `affected_vehicle_full_route`：**受影响车辆完整模拟路线**，非全车队总体收益；估算综合费用包括行驶费、车辆固定费、软时效罚金，不是全部成本；道路里程来自矩阵及比例估计，不是实车 GPS。
- `coverage_preserved=false` 或数据不可用时拒绝给出改善结论；未配置软时效则迟到改善显示 `—`；候选校验不通过不宣称收益。
- 这些卡片**不会**生成一个有收益的调度方案；场景是否有改善完全取决于服务端真实求解结果。
- `model_success` 代表服务端确认 DeepSeek 有效解释；`deepseek_tool_call` 代表解析阶段真实工具解析，与模型解释是两个独立环节。后端读取工具的 trace 不能冒充 DeepSeek 自主调用。
- 无数据库变更，无 API 变更，**不连接 5433/5434**、不运行 Alembic、不调用 DeepSeek、不推送 Git。

## 演示建议

1. 「联合调度」中选择已有 checked run；切换「调度助手」，生成候选后查看意图解析来源和 AI 证据卡。若无 Key，必须如实说明。
2. 「异常处置」中登记一条车辆延误，查看三方案卡、模型解释、独立校验，再人工审批。
3. 「仿真回放」切回 **当前调度车辆** 模式，看三列指标和二维地图方案对照。**四车场景演示**仅为地图视觉示例，不参与指标计算。
4. 若候选与简单顺延持平，展示“未证明费用改善”，解释算法是约束求解和可行性评估，不保证每次一定节省成本。
