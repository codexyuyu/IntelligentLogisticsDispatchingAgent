# 运输智能调度工作台 · 2026-10-30

## 入口

`#/vehicles` 对应 `apps/frontend/src/components/TransportWorkflow.tsx`。

## 本轮实现

- 页面布局改为：三车八单正常计划预览、数据库批量任务配置、结果 KPI、车辆任务列表、多车地图、候选审批。
- 数据库订单与车辆支持全选、清空、逐项勾选；`scope` 与 `/optimizations/transport` 请求都传入完整选中 ID 数组，仍由 OR-Tools 真正求解。
- 只能选用包含**所有选中订单取货、送货节点及所有选中车辆起终点**的矩阵；0 矩阵时禁用正式求解并说明原因，不构造假矩阵。
- 方案的成本、距离、未服务订单均来自后端求解结果。路线停靠点通过 `route_id` 匹配车辆路线，防止不同车辆记录串线。
- 在文昌校区二维地图展示后端停靠节点序列；地理几何仍是示意路线，与后端费用/距离无关。
- 复用三车八单演示会话中的故障前正常计划；无本地会话时点击加载调用已有 `/integration/showcase/vehicle-breakdown/solve`，仅读取其 `baseline`；这一演示**不是**数据库订单的求解结果，也不提交数据库。
- 保留候选人工确认、持久版本提交和回读以及历史联合运行回放；用户改变订单、车辆或矩阵时，清空旧候选，避免错提交。

## 验收建议

1. 页面无数据库矩阵时应明确提示并禁用正式求解；三车八单演示计划可单独加载。
2. 数据库具备覆盖矩阵后，选择多单多车，检查 Network 的 `POST /optimizations/transport` 请求，其中 `order_ids` 和 `vehicle_ids` 必须是多元素数组。
3. 求解完成后核对 `solution.candidate.routes` 与 `solution.stops` 按 `route_id` 关联；不能把全部 stop 显示在每辆车下。
4. 勾选范围变化后，上一候选及其审批按钮应立即消失；只能审批当前通过校验的候选。
5. 三车演示与异常处置相同车辆、相同订单和示范坐标，地图标注模拟轨迹。发生故障、AI 工具调用和审批仍在「异常处置」完成。

## 本轮未做

- 未自动生成/写入距离矩阵，未修改后端求解器、故障救援或其他业务数据。
- 未提供缺失同口径基线时的“优化降低 X%”虚假对比；综合费用为后端结果。
- 未接通真实地图导航和 GPS。
- 未访问 5433 或 5434，未运行数据库迁移、未 push Git。

## 环境检查

TypeScript (`tsc --noEmit`) 已通过。当前验证容器缺 `@rollup/rollup-linux-x64-gnu`，无法完成 Vite 生产构建；真实批量求解还需要在安装 OR-Tools、存在矩阵的本地环境执行。
