# 文昌校区二维回放 · 车辆闪烁与瞬移修复

## 问题根因

1. 旧组件在每次仿真时刻推进时调用 Leaflet `marker.setIcon()`，导致图标 DOM 被反复替换，在浏览器里呈现约每秒一次的闪现。
2. 旧 `separateScreenMarkers` 每次计算屏幕距离，一旦两车跨越 36px 距离阈值，会突然为标记增加 24–88px 的偏移，呈现明显横跳。地图坐标是绘制用的模拟路径，并非真实道路导航。
3. 旧地图只按 React 的整秒状态更新 marker 的 `setLatLng`，尤其在 10x/30x 播放时位置大幅跳步。

## 修复

- Leaflet 车辆 Marker 只在地图 / 轨迹更换时创建，播放推进不再执行 `setIcon`；选中与异常仅切换图标现有 DOM 的 CSS class。
- 用 `requestAnimationFrame` 对后端的仿真时间进行小数秒插值，按对应车辆自己的 `DemoMapMotion` 中的可视折线连续前进。切换方案、拖动进度条、暂停后直接以所选后端仿真时刻为准；不修改持久化时间。
- 移除逐帧碰撞阈值跳位算法。多车共用仓库装卸点时，采用按车辆 ID 顺序确定的固定屏幕停车位置，发车 45 秒内平滑收敛到示意路径；回库前平滑展开。在途位置与画出的路线完全一致。
- 修复局部在线瓦片加载失败导致整张地图切到离线预览的问题：只有连续加载失败且完全没有成功瓦片时才显示离线画面，恢复成功后自动退出。
- 用户缩放地图后重新计算停车位视觉展开，避免缩放后错位。

## 本地检查

- `cd apps/frontend && npx tsc --noEmit -p tsconfig.json`
- `node apps/frontend/scripts/check-wenchang-motion.cjs`
- `cd apps/frontend && npm test -- src/lib/liuzhouDemoMap.test.ts`

本环境通过 TS 静态检查以及纯 Node 运动回归（四车 209,600 个采样，连续，零停靠点跳跃）。Vitest / Vite 标准构建仍受本环境缺少 `@rollup/rollup-linux-x64-gnu` 限制，尚不能声称浏览器已实测。

## 最终验收步骤（仅一轮）

1. 启动现有前后端，打开「仿真回放」和文昌校区地图。
2. 选择「四车场景演示」，1x 播放一次并切到 10x/30x 观察；每辆车始终沿自己的彩色模拟折线走，不应频繁消失或横跳。
3. 在共享仓库位置观察车辆停车区分和发车后平滑汇入路线；选车、跟随、缩放、暂停、拖动时间轴、回到起点。
4. 切回「当前调度车辆」验证真实载入车辆数量不变；检查 v0 / 候选同步对照。
5. 本次未连接任何 PostgreSQL 实例，未修改 5433/5434、未更改数据库迁移、求解器、成本或审批逻辑；队友单仓三维模型不动。

**路线标识：** 地图底图是真实 OSM 街区，但配送点和行驶折线属于示范映射，并非高德/OSM 路径规划路线。之后接真实导航 API 可替换 `demoLegGeometry`，不需要改时间轴/轨迹采样接口。
