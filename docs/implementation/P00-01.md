## 2. 接口/单位

本任务在任务包中声明的公开入口：

```text
BaselineInventory(source_path, sha256, owner, capability, disposition) -> MigrationMap
```

落到已交付制品上的字段对应关系（`BASELINE_INVENTORY.json` 的 `entries[]` 一行即一个 `BaselineInventory` 输入，整份清单即 `MigrationMap` 的输出载体）：

| 签名参数 | 清单字段 | 取值与约束 |
| --- | --- | --- |
| `source_path` | `source_path` | 相对仓库根的旧路径；`entries` 中恰好出现一次 |
| `sha256` | `sha256` | 真实文件为 64 位十六进制小写 sha256；冻结边界为 `null` |
| `owner` | `owner` | `A` 或 `B`；沿用旧 `demo/OWNERSHIP.json` 的最长前缀匹配口径（未匹配默认 `A`） |
| `capability` | `capability_evidence` | 一句话能力证据；scaffold 条目必须显式写明未实现 |
| `disposition` | `disposition` | `reference` / `adapt` / `rewrite` / `reuse` 四类之一 |

- 哈希单位：`hash_algorithm = "sha256"`，对文件字节直接计算，无规范化、无换行转换。
- 版本单位：`schema_version = "1.0.0"`、`plan_version = "1.0.0"`、`baseline_date = "2026-09-10"`、`source_root = "demo/"`。
- 本任务不定义时间、长度、质量、温度单位，也不产生任何求解数据；单位口径以 `P00-02` 冻结的契约文档为准。

## 3. 输入输出样例

输入侧的关键约束（`uniqueness_rules`，逐字摘录自磁盘上的 `docs/architecture/BASELINE_INVENTORY.json`）：

```json
"uniqueness_rules": [
  "每个 source_path 恰好一条记录",
  "同一 target_path 可被多个 source_path 归并(例如旧HTTP DTO共同重写到新边界包)",
```

## 4. 状态与失败语义

- **生成器状态**：Python 进程退出码是唯一权威信号。`--check` 一致 → 0；不一致或缺文件 → 1 并打印 `BASELINE_INVENTORY.json is stale; regenerate it`；条目声明的旧源文件缺失 → `SystemExit`（`baseline source missing: ...`）；未列入清单的冻结边界路径不存在 → `SystemExit`（`excluded baseline entry missing: ...`）。这些失败都不写任何文件。
- **旧基线的运行期失败语义**：`demo/` 的未实现能力抛 `FeatureNotImplemented`，其 HTTP 表现为 501 + `not_implemented`。本任务把这个事实登记为能力证据，不把它当作实现；v1 的 typed 错误码（`INVALID_INPUT` → 422 等）由 `P00-02` 冻结、`P05-01` 起实现。
- **唯一性失败语义**：同一 `source_path` 出现两次、或同一唯一可交付文档被第二个 `source_path` 声明为主文档，都是必须失败的状态（双主契约与生成物漂移）。同一 `target_path` 被多个 `source_path` 归并是允许的（例如 24 条旧后端文件归并到 `apps/backend/src/logistics_backend/__init__.py`）。
- **迁移完整性语义**：`disposition=rewrite` 必须给出 `target_path` 或 `null`；`null` 表示明确不迁移（旧 `openapi.json`、`schemas.json` 即属此类）。
- **未登记即不迁移**：未在映射中的旧文件默认只读留存；例如 `demo/benchmarks/**` 只有子目录说明文件，未进清单，也不在映射范围内，不因「看起来有用」而迁入新仓库。

## 5. 实际限制

1. 本任务不执行任何应用测试：没有运行 `demo/` 的任何测试、没有启动旧应用、没有验证 501 之外的行为；第 1 节的能力边界结论来自旧源码中显式的 `FeatureNotImplemented`、`not_implemented` 样例与 scaffold 说明，不是运行结果。
2. 清单只证明「基线日期存在哪些文件、内容哈希是否与清单一致、旧代码声明的能力边界是什么」，不证明任何行为正确。
3. 无数据库、求解器、仿真、矩阵提供器与 LLM 供应方的可运行性证据；7 条 `reuse` 资产当前不具备复用生效条件，必须在对应任务重新验证后才可复用。
4. 未做单位一致性验证：v0.1 与 v1 的字段/单位/枚举映射只在 `MIGRATION_MAP.md` 第 3 节登记，尚未由实现或导出物验证。
5. 覆盖范围限于清单条目：`demo/` 下存在未列入的说明性文件（各子目录 `README.md` 等），它们未被登记、未被哈希、不被清单保证。
6. `apps/**`、`packages/**`、`contracts/**`、`tests/**`、根 `OWNERSHIP.json` 等目标路径在对应任务交付前均不存在；本任务不创建它们，也不声称它们可用。
7. 本任务不为 `G00` 签收提供业务证据：`G00` 判定「旧 demo 资产有逐项证据」，但签收由规划检查器单独记录，本轮静态报告不能替代业务签收。
