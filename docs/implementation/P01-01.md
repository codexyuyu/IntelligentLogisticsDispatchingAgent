# P01-01 · 目标 Monorepo 与可复现依赖环境

计划版本 1.0.0 · 阶段 Phase 01「Monorepo 与工程基础」 · 任务 ID `P01-01` · 负责方 A · 阶段 Gate G01

## 1. 已实现能力

本任务只交付**工程骨架与可复现依赖环境**，不含任何业务能力。已实现：

1. **Python workspace（uv）**：根 `pyproject.toml` 是聚合根（`package = false`），`[tool.uv.workspace] members = ["packages/*", "apps/backend"]`，并把 7 个成员全部声明为根依赖，使干净检出下 `uv sync --frozen` 一次装齐全部成员；成员间依赖一律用 `[tool.uv.sources] ... = { workspace = true }` 解析到工作区路径，不允许走索引。
2. **六个包 + 后端应用，src-layout**：
   `packages/{domain,contracts,optimization,simulation,agents,evaluation}/src/logistics_<name>` 与 `apps/backend/src/logistics_backend`，构建后端统一 hatchling。包名与目录名不一致（连字符 vs 下划线）由 hatchling 的 `targets.wheel.packages` 显式声明。
3. **可复现锁**：`uv.lock`（lock format version 1，40 个已解析包，含 `ortools 9.15.6755`、`simpy 4.1.2`、`fastapi 0.141.1`、`pydantic 2.13.5`、`pytest 9.1.1`、`ruff 0.16.7`）；`package-lock.json`（`lockfileVersion` 3，记录 npm workspace 与 `@playwright/test 1.63.0` 的 sha512 integrity）。锁文件由真实安装生成，未手写。
4. **npm workspace**：根 `package.json`（`private`、`workspaces: ["apps/frontend"]`、`engines.node = ">=22 <25"`）；`apps/frontend/package.json` 声明 `dev/build/test/contracts:generate/contracts:check` 脚本契约（`build` 先 `tsc -b` 再 `vite build`）。
5. **兼容基线固定**：`.python-version` = `3.12`，`.node-version` = `22`；本机实际验证的运行时为 CPython 3.12.10 与 Node 24.18.0（24 在 `>=22 <25` 兼容区间内，22 是兼容基线而非"最新版本承诺"）。
6. **E2E 运行器配置**：根 `playwright.config.ts`，`testDir = ./apps/frontend/e2e`，产物落 `artifacts/e2e/`，baseURL 默认 `http://127.0.0.1:5173` 且可用 `PLAYWRIGHT_BASE_URL` 覆盖。
7. **失败显式化**：七个 `__init__.py` 都是"可导入 + 未交付名字显式失败"的公开入口：模块级常量（`SCHEMA_VERSION = "1.0.0"`、`PACKAGE_NAME`、层名、契约版本）真实可用，后续任务才交付的名字经 `__getattr__` 抛 `NotImplementedError` 并附负责任务 ID。因此未实现能力**不会返回固定成功值**，也不存在 TODO 占位核心逻辑。

未创建任何业务实体、求解器、仿真内核、路由或 UI 组件；这些由 P02 及之后的任务交付。

## 2. 接口/单位

任务包声明的公开入口：

```text
workspace install -> import logistics_domain, logistics_contracts, logistics_optimization, logistics_simulation, logistics_agents, logistics_evaluation
```

落到制品上的精确对应：

| 入口/制品 | 路径 | 说明 |
| --- | --- | --- |
| 工作区安装 | `uv sync --frozen` | 读取 `pyproject.toml` + `uv.lock`，安装 7 个成员与全部依赖 |
| 六包导入 | `packages/*/src/logistics_*` | 由 `uv run pytest` / `uv run python` 从仓库根导入 |
| 后端入口 | `apps/backend/src/logistics_backend` | 组合根与 HTTP 边的唯一装配点（P05-01 实现） |
| npm 工作区安装 | `npm ci` | 读取 `package.json` + `package-lock.json` |
| E2E 入口 | `playwright.config.ts` | 根脚本 `npm run test:e2e` |

单位与契约口径（本任务只冻结常量，不实现业务）：`SCHEMA_VERSION = "1.0.0"`；`logistics_domain.LEGACY_CONTRACT_VERSION = "0.1.0"`（旧 demo 契约版本，只作迁移输入）；`logistics_backend.API_PREFIX = "/api/v1"`。共享单位（整数秒/米/克/cm³/分/decic、UTC epoch、`[start,end)` 占用、边界 `extra=forbid`）由 P02 起的领域类型强制，本任务不新建第二套单位定义。

## 4. 状态与失败语义

| 情形 | 期望行为 | 实现位置 |
| --- | --- | --- |
| 依赖未锁定/清单漂移 | `uv lock --check` 退出码非零；`uv sync --frozen` 拒绝解析 | `uv.lock` + 集成测试 |
| 成员未声明为根依赖 | 干净安装后该包导入失败（ModuleNotFoundError），不会被静默忽略 | 根 `pyproject.toml` + 集成测试 |
| `npm ci` 后锁文件被改写 | 集成测试断言两次运行前后 `package-lock.json` 字节不变 | 测试用例 2 |
| 未交付能力被调用 | `NotImplementedError`，消息带负责任务 ID 与契约位置 | 七个 `__init__.py` |
| 旧 demo 被改动 | 证据指纹比对失败（`demo/` 173 文件树 hash + `demo.zip` sha256） | 集成测试 |
| 运行时版本超出基线 | 单元/集成测试断言 `.python-version`/`.node-version` 与真实解释器版本 | 测试 |
| 缺 uv / npm 可执行文件 | 测试直接失败并说明工具缺失（不 skip、不静默通过） | 集成测试 |

错误码映射（INVALID_INPUT 等）由 HTTP 边界在 P05-01 实现；本任务不产生业务错误路径，也不得把未实现包装成成功。

## 5. 实际限制

- 只有工程骨架：无领域实体、无求解器、无仿真、无 API 路由、无前端源码。根 `pyproject.toml` 声明的 `readme = "README.md"` 指向的 `README.md` 在本检出中不存在；因为 `package = false`，hatchling 不会被要求构建根项目，所以不影响安装，但若要构建根发行物必须先补该文件。
- `apps/frontend/scripts/generate-contracts.mjs` 尚不存在（P24-02 交付），因此 `npm run contracts:generate` / `contracts:check` 现在会失败；`npm ci` 与 `npm run build` 的依赖前置不依赖它。
- Playwright 已安装并配置，但 P24-01 之前没有任何 e2e spec，**空 Playwright 运行不是验收证据**。
- 宿主未全局安装 `uv`（`Get-Command uv` 失败）。本任务把官方 PyPI wheel 解包到 `tools/bin/uv.exe`（0.12.13）用于执行与取证；该文件不属于本任务 Files 白名单，属于可删除的临时工具，交付环境应改用官方安装方式。
- 仓库当前没有 Git 仓库，`code_revision` 使用相关产物内容 hash 代替 Git HEAD + dirty 树 hash。
- 旧 `demo/` 出现的 `demo/backend/.pytest_cache/**` 是历史遗留文件（不属于登记的 173 个文件），本任务没有删除它；`demo/` 的只读断言只覆盖基线清单登记的 173 个文件与 `demo.zip`。
