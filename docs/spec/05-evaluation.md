# 可信性与评测

本项目不承诺消除所有大模型错误。目标是阻止未经核实的数据和方案进入执行，量化需求理解、求解可行性、解释忠实度与运行速度。以下全部为待实现的测试设计，不是实验结论。

## 三种错误分别处理

| 错误 | 例子 | 控制与测量 |
| --- | --- | --- |
| 需求理解错误 | “2 吨”解析成 2 kg，遗漏必须冷冻 | 原文定位、单位核验、缺项追问、结构化确认；测字段准确率和漏抽率 |
| 计划不可行 | 月台重叠、库容超限、未清洁就换批 | 独立规则逐条重新计算；发布前必须通过 |
| 解释不忠实 | 把可行解称为最优、捏造节省 30% | 数字由指标服务注入，解释绑定证据；不一致时模板回退 |

求解器只验证传给它的模型，不能发现原始自然语言被错误转录后产生的“可行”结果。自然语言产生的关键业务字段需展示原文与归一化值；温区、数量、截止时间、硬约束变更未确认时不得正式提交。完整的结构化表单或受信业务数据可直接走同一规划接口。

不依赖长链推理判断真假。每次模型调用记录模型标识、提示模板版本、工具输入输出、延迟、用量、拒答/重试、最终结构化结果与证据引用；不要求保存模型隐藏推理。密钥和客户隐私不入日志。

## 防幻觉闭环

需求 → 结构化草案 → 类型/单位/实体核验 → 原文及硬约束确认 → 快照固定 → 工具求解 → 独立联合校验 → 事实化解释 → 当前版本事务确认。

第一版无需向量数据库。库存、车辆位置和容量只从业务快照读取；规则使用带版本的结构化配置。若后续加入冷链手册问答，只检索有出处和生效日期的材料，不让检索文本直接变成执行指令。工具白名单、轮数限制和权限检查在模型外部实施。

常规请求目标最多 1 次抽取、1 次可选解释；输出格式修复最多重试 1 次，之后转表单或模板。可信的已结构化异常处理无需等待大模型。拒答、缺数据与未支持能力明确显示，不能填造假的默认值让流程继续。

## 独立校验测试集

| 类别 | 至少包含的反例 |
| --- | --- |
| 数据 | 缺温区、未知车辆、无效仓、2 吨/2000 kg 等价、负重量、倒置时窗、经纬度颠倒 |
| 自然语言 | 否定约束、冲突截止时间、漏抽关键字、非法 JSON、虚构 ID、要求跳过校验的提示注入 |
| 运输 | 重量合格但体积超限、单温区混装、空兼容车辆集合、漏单/重复单、跨站载荷错算、不可达边 |
| 仓储 | 跨时段重叠超容量、昨日入库今日重排漏计/保鲜重置、隔离库存被使用、清洁没占工人、前序未完成、跨午夜 |
| 联合 | 车先出发货后备好、到仓无月台、改仓无运输腿、两个子解分别可行但无法衔接 |
| 事件 | 故障改变已完成事实、执行中设备故障未记录中断和剩余量、在途货物瞬移、旧方案仍驶向故障仓、重复/乱序事件 |
| 事务 | 两计划争抢最后资源、重复确认、重排新旧预留重复占用、预留过期、确认期间快照变化、进程重启后重复扣库存 |
| 解释 | UNKNOWN 被称无解、FEASIBLE 被称最优、无基线却声称改善、模拟路况被称实时路况 |

独立校验器读取业务单位与最终计划，不能调用求解器相同建模函数来“证明自己”。采用小规模手工可核对案例、破坏候选计划的测试、关键边界的性质测试。并行线程和墙钟限时可能带来输出变化；复现包记录环境与参数，不承诺所有设备产生逐字节相同路线。

冷链特别回归项：Routing 的空允许车辆列表表示不添加限制，并不表示无车可用；温区筛选为空时必须在建模前处理。热启动路线也不等于冻结执行状态。[RoutingModel 类参考](https://or-tools.github.io/docs/python/classortools_1_1constraint__solver_1_1pywrapcp_1_1RoutingModel.html)

## 数据与对照设计

标准路径数据可用 [SINTEF Solomon VRPTW](https://www.sintef.no/projectweb/top/vrptw/100-customers/) 做独立算法核对。它不是冷链业务数据。原基准采用先车辆数、后距离的比较口径，使用不同目标、单位或舍入时不能直接声称超越其结果。

项目主实验用版本化合成场景：2/3 个仓、20/50/100 单、4/6/10 车，库容拥挤度、时间窗紧张度与事件强度分层。温区、保鲜与清洁参数注明为导师确认的实验假设。开发、参数调优和最终测试的种子分别冻结，不用测试集反复调参。

四组最低对照：

1. **B0 规则**：最早截止期/先来先服务仓储 + 最近可行插入运输。
2. **B1 顺序优化**：同样引擎先仓后运，只做一轮，仍必须校验，未通过则记录未服务。
3. **B2 协同优化**：有界仓运反馈与独立校验。
4. **B3 动态对照**：从相同初始计划出发，在相同事件发生后比较局部与全量重排。

另外单独比较人工标注约束与 LLM 抽取约束，测理解损失和用户交互成本；同一结构化输入加入 LLM 解释，不应被当成优化器提升。PyVRP/VROOM 仅在双方共同支持的标准 VRPTW 子集做可选外部对照。

每组至少 10 个固定测试种子，关键结论扩展至 30 个配对种子；记录失败和超时，报告均值、波动及配对差异。随机事件在场景时钟上外生生成，不让不同策略因随机数消费顺序不同遇到不同天气；策略都不能预先看到未来事件。推演分支若加入预测事件，须把预测来源和误差假设单独标注。

## 指标定义

| 指标 | 明确口径 |
| --- | --- |
| 需求满足率 | 已完成服务订单 / 到评估窗口截止应服务的有效订单；同时列取消、拒绝、延期和未完成 |
| 准时率 | 在软期望完成时刻前完成 / 已服务订单；没有软期望时使用业务定义的交付截止。并列按全部应服务订单计算的准时覆盖率，另测硬时窗违规 |
| 硬约束违规 | 已发布计划违规数、执行中实际/模拟违规数分别统计；不能只统计最后成功的计划 |
| 设施利用率 | 各类资源占用量时间积分 / 可用容量时间积分；不同单位资源不能直接相加 |
| 成本与里程 | 相同服务需求和未服务惩罚下对比；拆列车辆固定成本、距离、延误、拒单 |
| 局部扰动 | 改车/改仓数量、开始时间偏移、路线次序变化；冻结事实改变必须为 0 |
| 异常恢复 | 事件入库到新方案验证完成的墙钟时间；等待用户确认另列 |
| 模型可信性 | 关键字段准确率、漏抽率、应追问召回率、误拒率、解释证据覆盖率、错误事实数 |
| 冷链暴露 | 离开合规冷区到重新进入合规冷区的时长代理；不等同真实温度、损耗或食品安全 |
| 资源与费用 | CPU、峰值内存、队列长度、模型调用次数/用量；金额按实际供应方账单计算 |

零违规必须同时报告服务覆盖率，不能通过拒绝全部订单获得漂亮指标。完整可行测试样例要求全部服务；刻意不可行的样例要求准确展示未服务与原因。

## 性能预算与门槛

暂定测试环境为 8 个逻辑 CPU、16 GB 内存，无本地大模型推理、矩阵已准备；实现时记录实际电脑、OS、进程/线程数。下列是第 2 周要校准的验收目标，不能写进材料作为已实现性能。

| 测项 | 初始目标 |
| --- | --- |
| 普通读取与作业提交 | P95 ≤ 500 ms；不含后台计算 |
| 50 单静态联合规划 | 共享求解预算 10 s；候选准备、校验与排队另列 |
| 常见局部异常，受影响 ≤ 15 单 | 事件入库到验证完成 P95 ≤ 3 s；不含 LLM、网络路网生成、人工确认 |
| 100 单联合规划 | 30 s 预算压力测试；必须报告覆盖率及超时，未达标时调整演示规模 |
| 确认与版本检查 | P95 ≤ 500 ms，失败也计入分布 |
| 模型交互 | 独立统计端到端 P50/P95；设置超时并提供表单，首 token 不当最终响应时间 |

先预热后测至少 30 次，冷启动、冷缓存、并发 1/2/4 分开报告。多轮求解总预算统一；公平对照必须同线程和同总计算预算。性能不达标先缩影响集、缓存矩阵、减少候选与明确范围，不删硬约束。

发布门槛：所有确认方案通过联合校验；关键语义反例不得越过确认；并发预留无双订；模型/地图断开仍可完成结构化演示；每个 R01-R10 有证据。缺陷分 P0 数据/计划错误、P1 核心功能不可用、P2 体验；P0/P1 未清零不封版。
